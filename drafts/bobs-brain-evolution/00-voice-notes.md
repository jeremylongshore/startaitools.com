# Voice pack — Jeremy (@asphaltcowb0y)

Pulled from: recent startaitools posts, live X, local x-threads + linkedin-posts, writing-guide + social-bundle.

## Opening patterns (do this)

1. **Cold failure first** — "A policy said deny… The agent got allow." (`empty-is-not-clean` / X same day)
2. **Doctrine line as thesis** — italic or bold one law early ("The kernel must not import its agents.")
3. **Named system + stakes** — name the repo/product in paragraph 2; say why it matters if the gate fails
4. **Numbers that earn trust** — "360 kernel tests… 52 leaf… 94% coverage" (X kernel post)
5. **Human was the safety** — "Manual save was safe because a human stood over it" (then automation forces the properties into code)

## Sentence rhythm

- Short declaratives. Concrete nouns. Real tool names (`Bash`, `agp watch`, `trust-bash`).
- Failure admitted in public (tautological evals, empty args, cron expand/contract order).
- Operator lens OK (trucking/restaurant implicit in LI personal voice; not forced into every post).
- First person fine when natural ("We pulled…", "I merged 14").
